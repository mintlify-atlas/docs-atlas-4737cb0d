`BaseRecipientAdapter` is a filterable adapter that queries the device's contacts database to provide autocomplete suggestions for email addresses or phone numbers.

## Overview

BaseRecipientAdapter extends `BaseAdapter` and implements `Filterable` to provide asynchronous contact searching. It queries both local contacts and directory sources, deduplicates results, and caches contact photos for performance.

### Key Features

- Queries contacts for email addresses or phone numbers
- Supports local contacts and remote directory sources
- Automatic photo fetching and caching
- Duplicate removal across data sources
- Configurable result limits
- Account-specific contact prioritization

## Basic Usage

### Email Adapter

```java
// Simple email adapter with default settings
BaseRecipientAdapter emailAdapter = new BaseRecipientAdapter(context);
recipientEditTextView.setAdapter(emailAdapter);
```

### Phone Adapter

```java
// Phone number adapter
BaseRecipientAdapter phoneAdapter = new BaseRecipientAdapter(
    BaseRecipientAdapter.QUERY_TYPE_PHONE,
    context
);

// Query only mobile phone numbers
phoneAdapter.setShowMobileOnly(true);

recipientEditTextView.setAdapter(phoneAdapter);
```

  Sets the account to prioritize in search results. When set, contacts from this account appear higher in the results.
  
  ```java
  Account account = new Account("user@example.com", "com.google");
  adapter.setAccount(account);
  ```
</ResponseField>

<ResponseField name="getAccount()" type="Account">
  Returns the currently set priority account, or null if none is set.

</ResponseField>

### Phone Number Filtering

<ResponseField name="setShowMobileOnly()" type="void">
  When set to true and using `QUERY_TYPE_PHONE`, only returns phone numbers marked as "mobile" type.
  
  ```java
  // Only show mobile phone numbers
  adapter.setShowMobileOnly(true);
  ```
  
  <Note>
    This setting only applies to phone number queries (`QUERY_TYPE_PHONE`). It has no effect on email queries.
  </Note>
</ResponseField>

<ResponseField name="isShowMobileOnly()" type="boolean">
  Returns whether the adapter is configured to show only mobile phone numbers.
  
  ```java
  boolean mobileOnly = adapter.isShowMobileOnly();
  ```
</ResponseField>

## How It Works

### Search Process

1. **User types** in RecipientEditTextView
2. **Filter activated** - Adapter receives the constraint (search query)
3. **Local search** - Queries default directory (device contacts)
4. **Results processed** - Duplicates removed, entries aggregated by contact
5. **Directory search** - If needed, queries additional directories (Exchange, etc.)
6. **Photos fetched** - Contact photos loaded asynchronously and cached
7. **Results displayed** - Adapter notifies RecipientEditTextView of updates

### Result Limits

The adapter uses `DEFAULT_PREFERRED_MAX_RESULT_COUNT` (10) as the default maximum number of results. This can be customized via the constructor:

```java
// Show up to 25 results
BaseRecipientAdapter adapter = new BaseRecipientAdapter(context, 25);
```

The adapter adds `ALLOWANCE_FOR_DUPLICATES` (5) extra entries to each query to account for duplicates that will be removed.

### Deduplication

Results are deduplicated based on destination (email address or phone number). If the same email/phone appears multiple times:

- Multiple addresses for the same contact are grouped together
- The first occurrence is shown as a top-level entry
- Additional addresses appear as second-level entries
- Duplicate destinations across different contacts are filtered out

### Photo Caching

Contact photos are cached in an LRU cache with a maximum size of 200 photos. Photos are fetched asynchronously to avoid blocking the UI thread:

```java
// Photos are automatically fetched and cached
// No manual intervention required
RecipientEntry entry = adapter.getItem(position);
byte[] photoBytes = entry.getPhotoBytes(); // May be null initially
```

## Directory Search

The adapter can search multiple contact directories:

- **Local contacts** - Device's primary contact storage
- **Exchange directories** - Corporate directory services
- **Other directories** - Third-party contact providers

Directory search is automatically triggered when local results are insufficient (less than the preferred max count).

### Directory Search Behavior

- Searches happen in parallel for better performance
- A "Waiting for more contacts" message shows if directory results are slow
- Results are merged with local contacts as they arrive
- Directory search respects the overall result limit

## Advanced Usage

### Custom Result Matching

```java
// Override getMatchingRecipients for custom matching logic
BaseRecipientAdapter customAdapter = new BaseRecipientAdapter(context) {
    @Override
    public Map<String, RecipientEntry> getMatchingRecipients(Set<String> addresses) {
        // Add custom recipient matching logic
        // Return map of address -> RecipientEntry
        return super.getMatchingRecipients(addresses);
    }
};
```

### Account-Specific Queries

```java
// Prioritize contacts from a specific account
Account workAccount = new Account("work@company.com", "com.google");
BaseRecipientAdapter adapter = new BaseRecipientAdapter(
    context,
    10,
    BaseRecipientAdapter.QUERY_TYPE_EMAIL
);
adapter.setAccount(workAccount);

// Contacts from work@company.com will appear first in results
```

## Performance Considerations

<Tip>
  - Photo fetching is limited to the first 20 visible items by default
  - Photos are cached in memory to reduce database queries
  - Directory searches happen asynchronously to avoid blocking the UI
  - Results are deduplicated to minimize the number of items displayed
</Tip>

<Warning>
  The adapter requires `READ_CONTACTS` permission to function. Ensure this permission is granted before creating the adapter.
</Warning>
